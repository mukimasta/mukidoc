# Overview

MukiDoc is a software engineering documentation method for developing with humans and AI together. Through a set of documents with clear structure and distinct responsibilities, it keeps a project's important context in the project itself, so that both humans and AI can understand the project, keep developing it, and stay consistent over long iteration.

**The problem.** Once AI joins development, generating and modifying code becomes easier and easier. But what really matters in a project (why it is designed this way, what state the system is in, what trade-offs were made before, whether a given implementation is a stopgap or a long-term design) still scatters easily across people's heads, chat logs and code details. As a project ages, humans must reread code to recover context, and an AI often needs everything re-explained in a new session. MukiDoc aims to keep this context stably in the project, so that the project can explain itself.

**Deliverables.** MukiDoc provides a methodology and documentation specification, a standalone AGENTS.md working protocol, and a bootstrap Skill and script that establish the fixed skeleton. The protocol is versioned with the bootstrap package, and existing projects may choose whether to update it. MukiCheck, which checks project health, and further migration and maintenance tooling are still to be built.

**User scenario.** A developer has a new idea. They first work it out with an AI, and the design result settles directly into the project documents; then they have the AI continue with system design and code implementation based on those documents. A few days later they think of a change. They do not need to recall which classes they wrote or which functions they changed; they open the documents, confirm the current design, and tell the AI the new requirement. As the AI modifies the code, it updates the affected documents too. Months later a new Agent takes over. It does not need to inherit all the earlier chat history; by rereading the project it can tell what this thing is, why it is designed this way, how far it has come, and how to proceed.

With MukiDoc, even one person can hold the intent and structure of a complex project over the long term, let different AIs take over concrete development at any time, and turn context that once needed a whole team to maintain into a capability the project itself can preserve and carry forward.
