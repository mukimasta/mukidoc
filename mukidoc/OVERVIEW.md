# Overview

MukiDoc is a structured documentation protocol designed for large projects. It uses structured documents to keep a project's high-level context, such as its philosophy, architecture and roadmap, together with the core design-chain documents across three layers: Design → System Design → Implementation. The MukiDoc protocol gives these documents a clear structure; following it, AI grasps the project as a whole and maintains the documents as it writes code, keeping them clear, elegant and tidy.

**The problem.** AI makes code ever easier to generate and change, but what really matters in a project (why it is designed this way, what state the system is in, what trade-offs were made, whether an implementation is a stopgap or a long-term design) still scatters across people's heads, chat logs and code details. The longer a project runs, the more an individual forgets earlier judgments; the larger the team, the more unevenly information is held; and every new AI session needs everything re-explained. Existing memory systems let AI remember what happened, but not grasp the project as a whole; and without structure, AI can hardly keep documentation in good shape for long.

**Deliverables.** MukiDoc provides a methodology and documentation specification, a standalone AGENTS.md working protocol, and a bootstrap Skill and script that establish the fixed skeleton. The protocol is versioned with the bootstrap package, and existing projects may choose whether to update it. MukiCheck, which checks project health, and further migration and maintenance tooling are still to be built.

**User scenario.** A developer has a new idea. They first think through what problem it solves and what it should be, write the vision and design into the upper-layer documents, refine it into a system design together with an AI, and let the AI implement the code. Weeks later they want a change. They do not need to recall which classes and functions they wrote; they open the documents, confirm the design and the earlier decisions, and tell the AI the new requirement. The AI understands where the change sits in the whole, and as it modifies the code it updates the affected documents in the right places. Months later a new teammate or a new Agent joins. Without any earlier chat history, they can read the project and tell what it is, why it is designed this way, how far it has come, and how to proceed.

With MukiDoc, a project's vision and direction stay in human hands, its knowledge no longer depends on anyone's memory, and AI, working from a full global view, can take on more and more of the development.
